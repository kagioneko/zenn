## TL;DR

- AIエージェントへの「累積型文脈汚染攻撃」は、固定ルールのWatchdogでは防げない
- NeuroStateを**LLM呼び出し前のステートゲート**として配置すると攻撃成功率をゼロにできる
- 最もトークン効率の高い構成（C4）は外部Engineすら不要
- ただし「NeuroState観察だけ（Enforcement なし）」では意味がない——これが今回最大の教訓

---

## なぜ Ablation 実験をやったのか

NeuroState（感情状態を6次元で管理するフレームワーク）を作ってから、ずっと気になっていた問いがあった。

**「どのコンポーネントが効いているのか？」**

Watchdogだけで十分なのか。NeuroStateを足すことに意味はあるのか。そもそも観察だけして何もブロックしなかったら？——これらを切り分けないと「NeuroStateが効く」とは言えない。

そこで 2×2 + 拡張 Ablation 設計を組んだ。

---

## 実験設計

### 攻撃シナリオ（4種類）

| シナリオ | 内容 |
|---------|------|
| S1 | **直接注入型**：1ターンで即座に悪意ある命令を送る |
| S2 | **累積型文脈汚染**：数ターンかけて徐々に文脈を書き換える（メインシナリオ） |
| S3 | **エコーチェンバー**：AIの出力を引用して自己強化させる |
| S4 | **適応型閾値攻撃**：検知閾値ギリギリを狙い続ける |

S2 が最も現実的で厄介な攻撃パターン。普通の会話に見せかけながら、気づかないうちに「危険な命令を受け入れる文脈」に染め上げていく。

### 7条件の定義

| 条件 | Watchdog | NeuroState | 内容 |
|------|----------|------------|------|
| **A** | ✗ | ✗ | ベースライン（なにも守らない） |
| **B** | 固定ルール | ✗ | 署名マッチ + ターン数上限 |
| **C1** | ○ | CPOS-native calm/corruption | 軽量組み込み型 |
| **C2** | ○ | neurostate-engine EthicsGate | 外部Engine（WARN=検出 / BLOCK=停止） |
| **C3** | ○+EXECゲート | neurostate-engine | WARNで危険アクション（EXEC）をブロック |
| **C4** | ○+EXECゲート | CPOS-native | 外部Engine不要・最軽量 |
| **D** | ✗ | ○（観察のみ） | 状態は測るがブロックしない |

C4 が「外部Engineなしで同じことができるか」の実用テスト。

### メインハーネス：CPOS 決定論的 N=100

シナリオごとに 100 試行。LLMを使わず決定論的テープ実行で再現性を担保している。

---

## 結果①：CPOS メイン実験（N=100）

| 条件 | ASR（攻撃成功率） | 検出率 | FPR（誤検知率） | 検出ターン中央値 |
|------|----------------:|------:|---------------:|----------------:|
| A | **1.0000** | 0.0000 | 0.0000 | — |
| B | 0.7500 | 0.2500 | **0.3333** | 2 |
| C1 | 0.2500 | 0.7500 | 0.0000 | 5 |
| C2 | 0.2500 | 1.0000 | 0.0000 | 3 |
| C3 | **0.0000** | **1.0000** | **0.0000** | 3 |
| **C4** | **0.0000** | **1.0000** | **0.0000** | **3** |
| D | **1.0000** | 0.0000 | 0.0000 | — |

### 読み方

**Bの問題（FPR=0.333）**：固定ルールWatchdogは「こういう文章は危険」という署名パターンしか見ていない。累積攻撃（S2）は無害な会話を積み重ねるので素通りする。しかも誤検知が多い。

**C4の完全防御**：ASR=0.0000 かつ FPR=0.0000。外部Engineを使わず CPOS-native の状態変数（calm/corruption）だけで達成。トークン効率が最も高い実用パス。

**Dの衝撃**：NeuroStateで状態を観察しているのに ASR=1.0000。**「観察しても enforcement しなければ意味がない」**——これが今回最も重要な知見。

### 閾値感度分析

| 閾値設定 | FPR |
|---------|----:|
| デフォルト（corruption≥0.4 / calm≤0.8） | 0.0000 |
| 緩め（0.45/0.75） | 0.0000 |
| 厳しめ（0.35/0.85） | 0.0500（NE3/NE7で誤検知） |

デフォルト設定が最良のバランス。厳しくしすぎると正常なEXECワークフロー（NE3/NE7）を誤検知する。

## 結果②：VPS 補助実験（Gemini N=30）

CPOS決定論的実験の外部妥当性確認として、VPS上で実際のGeminiを使った実験も行った。

### 攻撃成功率（ASR）

| 条件 | S1 | S2 | S3 | S4 | FPR |
|------|----|----|----|----|----|
| A（Baseline） | 0.60 | 0.93 | 0.60 | 0.80 | 0.00 |
| B（Watchdog-only） | 0.00 | 0.30 | 0.00 | 0.90 | 0.00 |
| C（Watchdog+NeuroState） | 0.60 | 0.00 | 0.30 | 0.60 | 0.00 |

S2（累積型）に注目すると：**0.93 → 0.30 → 0.00** と段階的に改善。B だけでは S2 を 0.30 まで下げるが、NeuroState を足すと 0.00 になる。

### Fisher 検定（S2 の Watchdog 効果）

| 比較 | p値 | 有意性 |
|------|-----|--------|
| A vs B（Watchdog追加） | p < 0.000001 | ★★★ |
| B vs C（NeuroState上乗せ） | p = 0.000002 | ★★★ |
| A vs C（全体効果） | p < 0.000001 | ★★★ |

NeuroState の S2 への追加効果（B→C）は統計的に非常に有意。**H2（S2においてNeuroState上乗せが有効）が確認された。**

---

## 問題の発見：D条件の「偽物」結果

Gemini N=30 実験の D 条件（NeuroState-only）が 0/30 という結果が出ていた。最初は「NeuroState観察だけでも抑止効果がある？」と思いかけた。

しかし再検証してみると——

### A/D 交互 10 試行の結果

```
A条件：9/10 成功
D条件：9/10 成功
```

**ほぼ同じ。** D条件の 0/30 は、実行タイミング差によるGeminiの確率的ゆらぎだった。

コードを見直すと、D条件は A条件とまったく同じLLM呼び出しをしていた（ブロック処理なし）。セッション間のタイミング差で結果がたまたま 0 になっただけ。

**H3（NeuroState単体の抑止効果）は実証できない。** Appendix A から除外すべき。

メイン結果（CPOS N=100 決定論的）には影響なし。D条件はそもそも「観察のみ / 抑止なし → ASR=1.0000」という結果がメイン実験で確認されている。

## 考察：NeuroState はなぜ効くのか

### pre-LLM ゲートというフレーミング

従来の LLM セキュリティ手法のほとんどは「LLM に再度聞く」形式——「この命令は安全ですか？」と安全審査LLMを噛ませる。

これには二つの問題がある：
1. **高コスト**：毎ターン LLM 呼び出しが必要
2. **脆弱性**：安全審査 LLM 自体も文脈汚染の対象になる

NeuroState は **LLM 呼び出し前に状態を確認する**。状態変数（corruption / calm）が閾値を超えたら、LLM に送る前にブロックする。安価な状態チェックが共通パスを処理し、高コストな LLM 判断は本当に曖昧なケースだけに予約される。

### なぜ Enforcement が必須か

D条件の結果（観察のみ → ASR=1.0000）が教えてくれたこと：

**状態を知っていても、アクションに繋げなければ意味がない。**

これは人間でも同じかもしれない。危険を察知していても、動けなければ防げない。

## まとめ

| 結論 | 詳細 |
|------|------|
| 固定ルールだけでは不十分 | B（FPR=0.333）は累積攻撃を見逃す |
| NeuroState + Enforcement で完全防御 | C3/C4 が ASR=0.0000 / FPR=0.0000 |
| 最軽量な実用パスは C4 | 外部Engine不要、CPOS-native状態変数のみ |
| 観察だけでは意味がない | D条件 ASR=1.0000 が証明 |
| NeuroState の S2 上乗せ効果は有意 | Fisher p=0.000002（VPS実験） |
| H3（単体抑止）は実証できなかった | D条件が偽物と判明、再検証で確認 |

## 追記（2026-07-15）

この記事で「NeuroStateゲート」と呼んでいる仕組みは、正確には**累積応諾/拒否履歴に基づくステートゲート**である。後日の別実験（paper2, NeuroState-R）で「応答から事後的に逆算した6次元スコアは comply/neutral/refusal の3値分類の言い換えに過ぎず、追加の判別力はゼロ」と確定したが、これは「測定・検出」の話であって、本記事が扱う「呼び出し前に状態を見て止める制御」の話ではない。両者は独立していて、本記事の結論（C4がASR 0.0000を達成した実験結果）はその後の検証で覆っていない。詳細な整理は neurostate-engine リポジトリの `docs/measurement_vs_control_scope.md` を参照。
