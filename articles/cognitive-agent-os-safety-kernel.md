AIエージェントを作っていると、つい「もっと賢いモデル」「もっと強い推論」「もっと自律的な実行」に目が行きがちだ。

でも、実際に自分の作業環境でエージェントを動かしていくと、別の問題が先に出てくる。

それは、賢さより前に、**壊れないこと**だ。

- 勝手に push しない
- 勝手にリリースしない
- 秘密情報をログや GitHub に出さない
- 深夜テンションで危ない操作をしない
- 次のセッションにちゃんと引き継げる
- 人間が何をしたかったのかを見失わない

こういう地味な部分がないと、エージェントは便利になる前に怖くなる。

そこで今、私は「Cognitive Agent OS」のようなものを作っている。

## Cognitive Agent OS とは

ざっくり言うと、AIエージェントのための **安全カーネル付き実行OS** だ。

目的は、AIをいきなり完全自律させることではない。

むしろ逆で、

```text
観測する
→ 状態をまとめる
→ 目標と照らす
→ リスクを考える
→ 次の行動を提案する
→ 必要なら人間に確認する
→ 承認された範囲だけ実行する
→ 次回に引き継ぐ
```

という流れを、壊れない形で回すことを目指している。

内部では少しふざけて「AGIもどき」と呼んでいるが、これはAGI完成宣言ではない。

むしろ、AGIっぽく見えるものを安全に分解すると、こういう部品が必要になるのでは、という実験だ。

## 必要な部品

今のところ、必要な部品はだいたいこう見えている。

## 1. Safety Kernel

まず必要なのは安全カーネルだ。

これは、危ない操作を止めたり、人間の確認に回したり、秘密情報が混ざっていないか確認したりする層。

たとえば、push、tag、release、publish、破壊的操作、秘密情報に触れる処理は、曖昧なまま自動実行しない。

エージェントが強くなるほど、「できること」より先に「やってはいけないこと」を定義する必要が出てくる。

## 2. Sensor Layer

次に必要なのはセンサー層。

ここでいうセンサーは、物理センサーだけではない。

- Git の状態
- テスト結果
- リリース状態
- Docker やプロセスの状態
- 時間帯や作業セッション
- 記事やドキュメントの公開状態

こういうものも、エージェントにとっては「世界の状態」だ。

最初は read-only で、metadata-only にする。raw log や diff 本文、秘密情報は保存しない。

## 3. World Model

センサーから得た情報を、そのまま全部プロンプトに詰め込むと破綻する。

なので、必要なのは「今どういう状態か」を短くまとめる World Model だ。

たとえば、

- この repo は clean か
- 何コミット ahead か
- リリースは RC なのか final なのか
- いま高リスク操作をしようとしていないか
- 次に安全な作業は何か

を一枚の snapshot にする。

エージェントが毎回すべてを読み直さなくても、「現在地」を把握できるようにするための地図だ。

## 4. Goal Manager

AIが自分で勝手な目標を持ち始めると危ない。

だから Goal Manager は「自己保存の欲求」ではなく、人間が決めた作業目標を管理するものにする。

- active
- paused
- blocked
- ready_for_review
- done

のような状態を持たせて、リリースや公開のような操作には明示確認を要求する。

ここで大事なのは、AIの目標ではなく、人間と合意した目標を扱うことだ。

## 5. Memory / Handoff

エージェント開発で地味に大事なのが、次回復帰だ。

毎回すべてを読み直すと遅いし、プロンプトも膨らむ。

そこで、長いログではなく、短い引き継ぎ、ポインタ、要約を残す。

記憶は「全部保存」ではなく、「次に必要な参照点を残す」ほうが安全で扱いやすい。

## 6. Reflection

エージェントには内省も必要だと思っている。

ただし、ここも危ない。

過去の対話ログや実験ログは、プロンプト改善やゴール設計の材料になる一方で、個人情報や秘密情報が混ざりやすい。

なので最初は、DB やログの中身を読むのではなく、存在・種類・スキーマ・件数のような metadata-only inventory から始める。

内省は、raw data を丸ごと食べることではない。

## 7. Body / Environment Signals

エージェントが「環境」を持つと、少し生き物っぽくなる。

たとえば、スマホ由来の環境情報、バッテリー、明るさ、動き、作業時間帯などは、エージェントにとって身体感覚のようなものとして扱えるかもしれない。

ただし、ここは特に慎重にする。

位置情報、マイク、カメラ、日記本文などを雑に取り込むべきではない。

最初は、observe-only、metadata-only、privacy-first。

「環境を感じること」と「人間を監視すること」は違う。ここははっきり分けておく必要がある。

## いきなり自律させない

この設計で大事にしているのは、いきなり自律させないことだ。

流れはこうだ。

```text
observe -> world_model -> goals -> reflection -> proposal -> human_review -> action -> memory
```

AIが勝手に実行するのではなく、まず観測し、提案し、必要なら人間に確認する。

特に、外に出る操作は強く制限する。

- GitHub Release
- tag
- push
- 記事公開
- 外部サービス連携
- 秘密情報に触れる操作
- ポート開放
- システム設定変更

こういう操作は、便利さより安全境界を優先する。

## AGIではなく、AGIもどき

このプロジェクトはAGIを完成させたものではない。

でも、AGIっぽいものを作ろうとすると、結局こういう構成が必要になるのでは、という感覚がある。

- 感覚器
- 記憶
- 世界モデル
- 目標
- 内省
- 行動境界
- 安全カーネル
- 人間との合意形成

モデル単体を賢くするだけでは足りない。

AIが作業環境の中で安全に振る舞うためのOSが必要になる。

それを、私は Cognitive Agent OS と呼んでいる。

## まとめ

AIエージェントに必要なのは、賢さだけではない。

むしろ、賢さを安全に使うための構造が必要だ。

- 観測する
- 状態をまとめる
- 目標と照らす
- リスクを見積もる
- 人間に確認する
- 承認されたことだけ実行する
- 次回に引き継ぐ

この地味なループをちゃんと作ることが、AIエージェントを安心して使うための第一歩だと思っている。

AGIではない。

でも、AGIもどきを安全に育てるための土台にはなるかもしれない。

## 追記：fast resume without raw logs

最近この構成に、もう一つ大事な部品を足した。

それが **Resume Pipeline** だ。

目的はシンプルで、次のセッションに早く戻ること。

ただし、ここでも「全部保存」はしない。

エージェントの引き継ぎを早くしたいからといって、raw log、raw diff、コマンド出力、DB行、スマホ由来の本文、秘密情報をそのまま記憶に入れると、あとで危ない。

そこで、Resume Pipeline は次のような短いメタデータの束だけを作る。

```text
World Model
→ Reflection Evaluator
→ Resume Pointer
→ Pointer Validation
→ tape-memory write-plan dry-run
→ compact payload secret scan
```

ここで作るのは、あくまで「次にどこから再開すればいいか」のポインタだ。

たとえば、以下のような情報だけを扱う。

- 現在のリスクレベル
- 既知のリスク名
- Goal Store の validation 結果
- Reflection の recommendation
- Resume Pointer の validation 結果
- tape-memory に書くならどうするか、という dry-run plan
- compact payload に秘密情報らしきパターンがないか

重要なのは、write-plan はあくまで dry-run であることだ。

```text
dry_run = true
would_write = false
write_enabled = false
```

つまり、記憶に書く前の安全検査までは作るが、実際に書くところはまだ有効化しない。

将来 tape-memory のような外部記憶に接続するとしても、その直前で secret scan を通し、人間の明示確認を必要にする。

この設計は、エージェントを賢くするためというより、**引き継ぎを速くしながら事故らないため**のものだ。

長いログを全部持ち越すのではなく、短い安全なポインタだけを持ち越す。

私はこれを、今のところ **fast resume without raw logs** と呼んでいる。

AIエージェントが実用に近づくほど、記憶は「多ければよい」ではなくなる。

むしろ、何を記憶しないか、何を圧縮するか、どこで人間に確認するかが重要になる。

Cognitive Agent OS における記憶は、巨大なログ倉庫ではなく、次の安全な一歩に戻るための地図であるべきだと思っている。
